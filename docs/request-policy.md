# 重试与超时

在渠道「重试与映射」中设置普通重试、限流与空回重试、请求时限和返回状态码映射。

## 次数与默认值

| 设置 | 默认值 | 范围与含义 |
| --- | --- | --- |
| 渠道内部重试次数 | 0 | 0–10，不含首次发送 |
| 限流重试 | 关闭 | 首次有效输出前遇到可重试的限流响应时启用 |
| 空回重试 | 关闭 | 首次有效输出前遇到空响应或缺少完整结束的响应时启用 |
| 响应异常最大重试次数 | 3 | 0–10，限流与空回共享每次调用的额度 |
| 响应异常重试间隔 | 5 秒 | 1–3600 秒；限流响应要求更长等待时使用较长值 |
| 宿主默认尝试次数（含首次） | 1 | 插件设置中的 1–35 次默认值，用于未指定尝试次数的模型映射 |

普通重试与响应异常重试使用各自的额度。普通重试按「自动重试状态码」匹配，也适用于可重试的网络连接异常。状态码支持 100–599 的单值和包含端点的区间，以逗号分隔；留空表示不按状态码重试。

限流与空回重试使用同一 Key。启用 Key 自动禁用规则后，匹配状态码可在普通重试额度内切换 Key。一次调用及其内部重试固定使用同一渠道和代理。规则见 [Key 自动禁用与连接测试](key-auto-disable.md)。

外层每次尝试分别执行渠道的内部策略。例如外层尝试 3 次、渠道普通重试 2 次，最多普通发送 `3 × (1 + 2) = 9` 次；异常重试另按共享额度计算。次数表示上限，实际发送次数受响应结果、取消和时限约束。

## 输出与重试边界

正文、思考、密文、工具调用和音频均可构成有效输出。只有角色、Token 用量或结束标记不构成有效输出，缺少 Token 用量也不构成空回。

重试只发生在首次有效输出前。检测到有效输出或已向客户端交付流后，错误和断流会结束当前响应。已识别的永久性错误不进入限流或空回重试；普通参数错误不因空回选项而重试。请求被取消或执行时限耗尽后停止发送。

Responses 返回完整结束事件但没有有效输出时，开启空回重试可按共享额度再次发送；额度耗尽后返回 `502 empty_response`。缺少结束事件或异常断流分别标记为 `missing_terminal`、`stream_interrupted`。

限流识别同时参考 HTTP 429 和上游结构化错误。等待时间取配置间隔、`Retry-After` 和 `retry-after-ms` 中适用的较长值。空回重试可能重复上游执行与计费。

## 流与响应内容

SSE 按原始字节转发。Responses 的 `response.completed`、`response.done`，Messages 的 `message_stop`，以及 Chat Completions 的 `[DONE]` 用于识别完整结束。内容块结束或 `finish_reason` 不截断后续用量事件。

流式请求在首次有效输出前缓冲判断，开始输出后实时转发。非流式请求等待完整结果，必要时按原生协议汇总。输出前缓冲与非流式响应上限为 32 MiB。

## 时限

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| 响应头超时 | 60 秒 | 每次发送后等待上游开始响应的时间 |
| 总时限 | 180 秒 | 一次插件调用中全部发送、等待、重试和完整输出的总时间 |
| 流空闲超时 | 60 秒 | 读取响应时连续收不到新数据的最长时间 |

三项均支持 1–3600 秒，并受运行环境的执行预算约束。总时限到期会中断正在输出的流；流空闲超时只限制连续无数据的时间，持续输出也必须在总时限内完成。

「异常时剥离 Responses 资源状态」匹配明确资源错误时，最多额外重试一次，不占普通或响应异常重试额度，共用同一总时限。正常请求保留完整历史，规则见 [Responses 资源状态](../README.md#responses-资源状态)。

## 建议总时限

页面根据当前参数估算一次插件调用的等待预算：

```text
发送次数 = 1 + 普通重试次数 + 已启用的共享异常重试次数
基础建议 = 发送次数 × (响应头超时 + 流空闲超时)
         + 共享异常重试次数 × 重试间隔
         + 适用的 HTTP 520 退避
```

限流与空回同时开启时，共享额度只计一次。HTTP 520 的普通重试退避从 0.25 秒开始翻倍，单次最多 2 秒。计算结果向上取整，并受渠道及运行环境上限约束。

建议只计算一次插件调用，不乘外层尝试次数。运行环境的响应读取预算仅作上限，不加入建议值。估算不包含完整持续输出时间、错误响应的全部读取时间或上游临时要求的更长等待。长回答需要额外预留总时限；资源状态恢复也使用剩余预算。

修改相关参数会更新建议值。点击「填入建议」后保存渠道，或手动填写所需总时限。

## 状态码映射

映射将上游状态码替换为返回给客户端的状态码。源与目标支持 200–599，目标不能是 204、205、304。可使用可视化或 JSON 编辑器配置。

普通重试匹配和 Key 自动禁用使用上游原始状态码。将错误映射为 2xx 会使外层按成功响应处理，可能阻止继续尝试、目标切换或失败冷却。
