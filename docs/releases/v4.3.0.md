# UniversalForward v4.3.0

4.3 新增原生 Chat Completions、渠道认证方式选择和 Key 自动禁用，修复批量连接测试的 JSON 配额超限，并将 Responses 资源状态剥离改为仅在明确状态错误后触发。适配 Router2API 2.1.2 / Router.Contracts 2.0.0，运行时为 .NET 10，无需数据库结构迁移。

- 连接测试的 Job 只保存小型进度，结果摘要分页读取，响应原文按需分块加载。100 个模型 × Key 组合的大响应不再挤占宿主的进度与结果 JSON 配额；界面区分部分成功、已跳过、已取消和未执行，并保留 Key 名称。
- 渠道「Key 管理」新增自动禁用开关、HTTP 状态码和连续失败阈值。默认关闭，状态码默认 `401,403`，支持 400–599 单值与区间；阈值默认 3，支持 1–100。
- 同一独立请求对同一个 Key 最多累计一次失败，包含内部重试和宿主再次尝试。非匹配 HTTP 响应清零；网络异常、超时和取消不增减。判断使用原始 HTTP 状态码，状态码映射不影响计数。
- 正式请求命中规则后，在剩余普通重试次数和总时限内切换其他可用 Key，鉴权头随 Key 更新。达到阈值后持久化禁用状态，并从后续分配中排除；Key 列表显示原因、时间和来源，需手动重新启用。
- 连接测试新增独立的「本次测试允许自动禁用 Key」选项，默认不勾选。勾选时使用渠道规则，固定测试每行的 Key，后续组合跳过已禁用 Key。
- Responses 资源状态开关改为按错误触发：首次请求保留历史 reasoning、密文与条目 ID；只有上游明确报告状态失效且尚无有效输出时，才剥离并额外重试一次，共用总时限。普通 400、思考参数错误、限流和网络错误不触发。下一次请求仍保留完整历史；正常 compaction/item_reference 原样发送，失效时保留上游错误，不删除无法还原的上下文。
- 新增原生 Chat Completions `/v1/chat/completions`，配置键为 `chat`。支持 JSON、SSE、渠道端点与模型协议设置、独立请求头、思考等级映射、系统提示词及连接测试；保留工具调用、思考历史和扩展字段。已有渠道保持已保存的端点选择。
- Chat Completions 使用渠道所选认证和 HTTP/SSE；`finish_reason` 后继续读取用量直到 `[DONE]`，只返回思考密文或音频时也不会误判为空回。连接测试要求有效输出、正常结束原因和流结束标记，保留真实错误；完整 Chat 接口地址可用于 Base URL，转发和模型发现均正确拼接。
- 渠道「基础设置」新增认证方式选择，新建默认 `Authorization: Bearer`，可改为 `x-api-key`。选择作用于三种协议、模型获取、连接测试和 Responses WebSocket，Key 切换时重新生成认证头；切到 `x-api-key` 时清除 Bearer 前缀。复用现有高级参数保存，旧渠道的自动规则与自定义认证可继续保留，显式请求头覆盖仍优先。

未达到阈值的计数仅保留在当前进程，重启后清零；已禁用 Key 的状态在重启后保留。关闭自动禁用开关不会恢复已禁用 Key。测试原文总缓存上限 64 MiB，单条上限 32 MiB；完成任务最多保留 128 个、一小时，重载插件后清理。

详细配置、恢复方式与结果接口见 [Key 自动禁用与连接测试](../key-auto-disable.md)。

原生 Chat 配置和历史保留规则见 [Chat Completions](../chat-completions.md)。
