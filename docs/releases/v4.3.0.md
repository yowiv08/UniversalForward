# UniversalForward v4.3.0

4.3 修复批量连接测试的 JSON 配额超限，并增加按渠道配置的 Key 自动禁用与失败切换。适配 Router2API 2.1.2 / Router.Contracts 2.0.0，运行时为 .NET 10，无需数据库结构迁移。

- 连接测试的 Job 只保存小型进度，结果摘要分页读取，响应原文按需分块加载。100 个模型 × Key 组合的大响应不再挤占宿主的进度与结果 JSON 配额；界面区分部分成功、已跳过、已取消和未执行，并保留 Key 名称。
- 渠道「Key 管理」新增自动禁用开关、HTTP 状态码和连续失败阈值。默认关闭，状态码默认 `401,403`，支持 400–599 单值与区间；阈值默认 3，支持 1–100。
- 同一独立请求对同一个 Key 最多累计一次失败，包含内部重试和宿主再次尝试。非匹配 HTTP 响应清零；网络异常、超时和取消不增减。判断使用原始 HTTP 状态码，状态码映射不影响计数。
- 正式请求命中规则后，在剩余普通重试次数和总时限内切换其他可用 Key，鉴权头随 Key 更新。达到阈值后持久化禁用状态，并从后续分配中排除；Key 列表显示原因、时间和来源，需手动重新启用。
- 连接测试新增独立的「本次测试允许自动禁用 Key」选项，默认不勾选。勾选时使用渠道规则，固定测试每行的 Key，后续组合跳过已禁用 Key。

未达到阈值的计数仅保留在当前进程，重启后清零；已禁用 Key 的状态在重启后保留。关闭自动禁用开关不会恢复已禁用 Key。测试原文总缓存上限 64 MiB，单条上限 32 MiB；完成任务最多保留 128 个、一小时，重载插件后清理。

详细配置、恢复方式与结果接口见 [Key 自动禁用与连接测试](../key-auto-disable.md)。
