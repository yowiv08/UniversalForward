# UniversalForward v0.3.6

修复总时限建议把宿主最长读取时间直接当作推荐预留的问题：在响应头和流空闲均为 1 秒时，不再无条件建议等待十分钟。

- 基础建议按内部发送次数 ×（响应头超时 + 一个流空闲周期），加共享异常重试间隔和适用的 HTTP 520 退避，向上取整。宿主预算仅限制上限，不再抬高建议值。
- 普通重试 1 次、响应头与流空闲各 1 秒、限流／空回共享重试 1 次且间隔 2 秒、重试规则包含 520 时，基础预算为 `3 × (1 + 1) + 2 + 0.25 = 8.25` 秒，建议 9 秒。
- 建议区明确说明只估算基础等待，不含持续输出时间；长回答需额外增加总时限。流空闲周期不能用于推算完整模型输出时长，宿主各阶段及映射剩余预算继续生效。
- 保留默认折叠、一键填入、手动修改和保存方式。既有渠道配置不会自动改写，转发、两层重试、协议、Key、代理和明暗功能保持原有行为。

适配 Router2API 2.1.2 / Router.Contracts 2.0.0，运行时为 .NET 10，无需数据库迁移。

本次验证通过总时限建议、设置与持久化、官方 2.1.2 沙箱明暗交互三组浏览器测试，覆盖截图参数回归、宿主上限、手动值与草稿保留、明暗对比度及移动端布局；Release 构建及页面资源、模型发现、插件隔离共 5 项 .NET 检查通过。
