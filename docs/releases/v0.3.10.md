# UniversalForward v0.3.10

停止记录「插件收到的请求体」，避免把 Codex 工具定义、会话历史及长上下文复制进日志；补充 New API 使用的缓存写入字段兼容。适配 Router2API 2.1.2 / Router.Contracts 2.0.0，运行时为 .NET 10，无需数据库迁移。

- 收到的请求正文、实际发送正文、上游响应正文和 WebSocket 原文均不采集、不显示、不导出。采集、存储和页面同时过滤旧的 incoming／received 分段。请求元信息、模型、思考参数、请求／响应头、宿主扩展参数、错误及 Token 明细继续保留。
- 收到的请求只从已有 JSON 提取模型与思考参数，不为日志序列化、编码或复制完整请求正文。
- 缓存写入支持 OpenAI 输入明细中的 cache_write_tokens、cached_creation_tokens、cache_creation_input_tokens，保留 Claude 顶层总量；总量缺失时可使用明确报告的 OpenAI TTL 或 Claude 创建分项。同义总量不相加，重复事件不累加，OpenAI 输入不重复加缓存。
- 合法零值显示 0；缺失、无效和溢出保持「未返回」。不从输入差值或价格反推缓存写入，各次尝试独立记录。
- 日志遇到超大 SSE 事件后，在空行边界恢复后续事件的元数据提取，避免后续用量被一并遗漏。响应正文继续透传，转发汇总的原有上限保持不变。

缓存字段来源与 New API 实际处理方式见 [缓存用量核查](https://github.com/yowiv08/UniversalForward/blob/v0.3.10/docs/cache-usage.md)。单个超限 SSE 事件或超大普通 JSON 自身的元数据仍可能无法提取；上游未报告的缓存写入继续显示「未返回」。

请求日志及日志设置继续保存在本次运行内存，操作队列默认最多 256 项，满时丢弃日志操作并标记不完整。更新或重新加载插件会清空先前的内存日志。

本地验证通过 889 项插件测试（含发行隔离加载）、29 项 Router2API 2.1.2 宿主兼容性测试、日志查看／分页／复制／导出浏览器测试，以及 ZIP 和内容索引校验。
