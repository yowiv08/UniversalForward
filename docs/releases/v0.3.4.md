# UniversalForward v0.3.4

修复混合协议渠道中，未配置模型协议的 Claude 连接测试默认发送到 `/v1/responses` 的问题。

- 连接测试自动选择先遵循已保存的模型首选协议；未配置的 Claude 优先使用 `/v1/messages`，其他模型优先使用 `/v1/responses`，仅选择渠道启用的端点。
- 保留手动端点选择及模型支持协议限制，Claude 与 GPT 同批测试时分别选择端点，流式和非流式请求使用对应的请求体与认证方式。
- 开启模型协议配置时，根据模型名称和渠道端点提供初始选项；已保存的显式配置继续生效。
- 测试结果及详情显示测试端点，便于核对协议选择；桌面、手机和较矮窗口保持清晰布局。

兼容 Router2API 2.1.0 / Router.Contracts 2.0.0，运行时为 .NET 10。原渠道配置无需数据库迁移。普通转发仍按客户端接口与模型协议配置选路。

如果已有 Claude 模型显式选择 Responses，自动测试会继续遵循该设置；需要原生 Messages 时，在「模型与协议」中调整支持协议和首选协议。

下载 `universalforward.zip`，解压后更新插件目录。`release-index.json` 提供版本与文件校验信息。
