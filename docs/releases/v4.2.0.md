# UniversalForward v4.2.0

4.2 修复从 Anthropic 官方接口获取候选模型失败的问题，并容错末尾误填接口路径的 Base URL。适配 Router2API 2.1.2 / Router.Contracts 2.0.0，运行时为 .NET 10，沿用已有渠道配置，无需数据库迁移。

- 获取与刷新候选模型请求 `GET {Base URL}/v1/models` 时，默认附带 `anthropic-version: 2023-06-01`。此前该请求只带 `Authorization: Bearer`，Anthropic 官方接口返回 `400 anthropic-version: header is required`，渠道无法拉取模型；Messages 转发路径不受影响，一直带有该头。认证头仍默认 `Authorization: Bearer`，Anthropic 接受该形式；OpenAI 兼容上游忽略 `anthropic-version`。通用请求头或高级参数 `ReplaceHeaders` 配置的同名头继续覆盖默认值，不会重复发送。
- Base URL 末尾误带 `/v1/messages`、`/v1/responses` 或 `/v1/models` 时，去掉该接口段后按 `/v1` 前缀处理，大小写不敏感。此前会拼出 `.../v1/messages/v1/models` 并得到 404。模型获取、HTTP／WebSocket 转发、连接测试与诊断中的「请求地址」使用同一规则；已保存的 Base URL 不被改写。
- 排查提示：诊断中 `HTTP: 403` 且正文为 `Request not allowed`，表示请求在 Anthropic 边缘被地区限制拒绝，与请求头和 Key 无关，需要为渠道选择代理出站；`HTTP: 404` 多为 Base URL 包含多余路径。

沿用 4.1 的系统提示词角色调整与日志布局，以及 4.0 的 CPU 热点修复、正文日志移除和缓存 Token 解析。请求日志继续使用运行内存，更新或重新加载插件会清空此前日志；持久化渠道和插件设置保持原有格式。

本地验证通过 907 项插件测试和 29 项宿主兼容性测试，新增 12 项覆盖默认与覆盖后的版本头、Base URL 接口段容错及转发路径容错；并经代理对 Anthropic 官方 `GET /v1/models` 实测，以插件现在发送的请求头取回完整模型列表。界面未改动，未运行浏览器测试与发行包隔离加载脚本。

下载 `universalforward.zip`，校验信息见同一 Release 的 `release-index.json`。本次发布仅包含 UniversalForward 插件。模型获取与 Base URL 规则见 [README 模型配置](https://github.com/yowiv08/UniversalForward/blob/v4.2.0/README.md#模型配置)。
