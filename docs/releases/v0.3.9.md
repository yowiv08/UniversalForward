# UniversalForward v0.3.9

修复请求调用期间的 CPU 与垃圾回收热点，移除发送／响应正文日志，并增加输入、输出和缓存 Token 明细。适配 Router2API 2.1.2 / Router.Contracts 2.0.0，运行时为 .NET 10，无需数据库迁移。

- SSE 日志解析和非流式汇总只增量扫描新数据，不再每次读取复制、扫描整个未结束事件；保持 UTF-8 跨块、BOM、LF／CRLF／CR 和多行 data 处理。
- Claude 非流式汇总按内容块使用字符串缓冲，文本、思考和签名在块结束时一次写回，避免长回答的二次复制开销。
- 每次调用复用一份已验证的渠道配置，发送前在一个请求对象上完成模板、原生流、思考、系统提示词和资源状态规则，再序列化。身份匹配继续使用原始请求历史，内部重试复用最终发送内容。
- 日志不再保留实际发送正文、上游响应正文和 WebSocket 原始消息，查看和导出入口同步清理。插件收到的请求、宿主扩展参数、请求／响应头和错误信息继续保留。
- 模型目录失败和转发失败日志不再附带完整响应正文，保留 HTTP 状态、路径、类型和错误原因；模型获取的显式诊断结果仍可供管理员查看。
- 日志只在元数据变化时保存快照，队列溢出标记应用后清理，保留不完整标记和请求状态。
- 详情增加「Token 明细」，记录输入 Token、输出 Token、缓存读取和缓存写入，各次上游尝试独立记录，摘要使用最后一次尝试。合法零值显示 0，未报告或无效值显示「未返回」。Claude 输入总量包含缓存读写，OpenAI 输入已含缓存，不重复相加。

本地回归通过 827 项插件测试（包含发行加载隔离）、29 项真实宿主集成测试，以及日志、分页和页面导航浏览器验证。独立内存上游微基准覆盖 Claude 增量、1／2／4／8 MiB Responses 单行事件及碎片日志响应，逐次校验下游输出哈希；耗时和分配结果只代表相应处理路径，不等同于整机 CPU 降幅。

具体热点、微基准结果和验证范围见[请求 CPU 热点与验证](https://github.com/yowiv08/UniversalForward/blob/v0.3.9/docs/cpu-performance.md)。

日志元数据解析仍受 1 MiB 字符上限约束；超大 JSON 或单个 SSE 事件的模型、思考或 Token 字段可能未提取。非流式可从响应契约补输入／输出，缺失缓存计数显示「未返回」。原始网络响应继续完整转发。

插件请求日志及日志设置保存在本次运行内存，重启或重载后清空。日志操作队列默认最多 256 项，普通请求入队时不等待容量；满时丢弃日志操作并标记不完整。渠道、外观和执行设置继续使用各自已有的持久化方式。
