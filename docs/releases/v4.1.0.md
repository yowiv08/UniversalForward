# UniversalForward v4.1.0

4.1 提升渠道系统提示词在本次请求中的优先级，并修复请求日志的嵌套滚动与顶部控件占用过多空间的问题。适配 Router2API 2.1.2 / Router.Contracts 2.0.0，运行时为 .NET 10，沿用已有渠道配置，无需数据库迁移。

- Responses 追加模式将原 `instructions` 转为首条 `developer` 消息，将普通旧 `system` 消息改为 `developer`，插件提示词作为 `input` 最后一条独立 `system` 消息发送。顶层 `instructions` 保留为空字符串以兼容 Codex 上游，插件文本只写入一次。
- Responses 替换模式移除本次请求中的原 `instructions` 和普通 `system`／`developer` 指令消息，再写入插件系统消息。显式工具条目、动态工具声明及嵌套字段保留；字符串 `input` 转为原文不变的用户消息。
- Claude 使用顶层 `system` 块数组，插件提示词作为最后一个独立文本块；追加保留原块及缓存属性，替换保留插件文本及 Claude Code 模板要求的客户端身份段。Claude 系统块之间没有额外优先级字段，需要清除旧普通指令时使用替换。
- 提示词内容原样发送，包括空格、换行和占位符形式的字面文本；不自动添加前缀、后缀或“冲突时以插件规则为准”说明。HTTP、SSE、WebSocket、连接测试及重试共用处理流程，避免重复追加。日志只记录改写方式、角色、位置和处理数量等元数据。
- 插件页面使用 iframe 的可用高度，渠道内容在插件内滚动；请求日志的标题、筛选、表格和存储设置共用一个滚动区域，表格不另设纵向滚动，分页栏固定可见。手机端隐藏表头的定位限制在日志区域内，避免把插件文档撑高。
- 日志标题、记录数和操作合并为紧凑单行，缩小筛选控件，采集说明默认收起；日志正文保持原有可读字号。手机端保留完整操作及可滚动内容。

沿用 4.0 的 CPU 热点修复、请求／响应正文日志移除和缓存 Token 解析。请求日志继续使用运行内存，更新或重新加载插件会清空此前日志；持久化渠道和插件设置保持原有格式。

本地验证通过 896 项插件测试（含构建包隔离加载）、29 项宿主兼容性测试、系统提示词与日志相关浏览器测试，以及 160 组滚动布局检查。验证覆盖原文保持、角色和顺序、工具历史、HTTP／WebSocket 重试、Claude 缓存块和手机布局；未调用收费模型测量指令遵循概率。插件无法控制上游接收请求后追加的规则，动态工具声明保留原角色。

下载 `universalforward.zip`，校验信息见同一 Release 的 `release-index.json`。本次发布仅包含 UniversalForward 插件。系统提示词的协议行为见 [系统提示词设计](https://github.com/yowiv08/UniversalForward/blob/v4.1.0/docs/system-prompt.md)，页面布局见 [管理界面设计](https://github.com/yowiv08/UniversalForward/blob/v4.1.0/docs/web-design.md)。
