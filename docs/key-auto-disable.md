# Key 自动禁用与连接测试

渠道「Key 管理」可以分别配置正式请求开关、原始 HTTP 状态码和连续失败阈值。默认关闭，状态码为 `401,403`，阈值为 3；支持 400–599 单值及逗号分隔的区间，阈值为 1–100。

启用后，命中状态码立即排除该 Key 在本次请求中的后续选择，在剩余普通重试次数内按渠道策略换 Key。切换不增加总超时或重试预算；普通重试为 0 时不会增加发送。鉴权头与 `{api_key}` 占位符随 Key 更新，请求正文、会话身份和代理保持稳定。未达到阈值的 Key 仍可用于后续独立请求。

同一客户端请求的内部重试和宿主再次尝试，通过 Trace ID 去重，对同一 Key 最多累计一次；每个模型 × Key 测试组合使用独立标识。非匹配 HTTP 响应清零，网络异常、超时和取消不增减。仅匹配原始 HTTP 状态码，不匹配映射后的状态码，也不从 HTTP 200 的 JSON/SSE 业务错误推断 401/403。WebSocket 握手拒绝返回的 HTTP 状态码参与判断。

连续失败在当前进程内累计。禁用时通过宿主凭据 CAS 写入 `Enabled=false`、禁用时间、原始状态码、来源和累计次数，并更新 Key 配置版本及模型可用性。重启会清空未达到阈值的计数，已禁用 Key 保持禁用。保存冲突会重读并重试；保存失败时当前进程仍排除该 Key，界面提示保存失败，后续请求或刷新渠道列表继续尝试保存。

在 Key 列表勾选「启用」并保存，可手动恢复自动禁用的 Key。替换密钥、改变启用状态或修改自动禁用规则会重置对应计数，并使旧请求迟到的结果失效。关闭开关不会恢复已经禁用的 Key。并发旧编辑页面可能收到 409，需要重新加载后编辑，避免覆盖自动禁用结果。

连接测试有独立的「本次测试允许自动禁用 Key」选项，默认不勾选；勾选时使用渠道相同状态码和阈值，与正式请求开关无关。测试固定使用该行 Key，命中时结束本行且只记一次，后续组合跳过已禁用 Key。未勾选时不改计数或启用状态，保留原有测试重试方式。模型发现不参与失败计数。

## 结果读取

宿主 Job 的进度和最终结果只含 `completed`、`total`、`runningIndex`、`resultVersion`，不会附带响应原文或累计结果数组。

| 插件相对接口 | 用途 |
| --- | --- |
| `POST tests/start` | 原有参数加 `autoDisableKeys`，默认 false；序列化输入超过 64 KiB 时返回中文校验错误 |
| `GET tests/status?id=…` | 读取 Job 状态及小型进度 |
| `GET tests/results?id=…&offset=0` | 每页最多 20 条摘要，返回 `rows`、`total`、`nextOffset`、`resultVersion` |
| `GET tests/detail?id=…&rowId=0&offset=0` | 按 UTF-8 字节位置读取最多 64 KiB 原文，返回 `text`、`nextOffset`、`done`、`truncated`、`evicted` |
| `POST tests/cancel` | 沿用原接口，取消后保留已经完成的记录 |

摘要中的 `state` 区分 queued、running、succeeded、failed、skipped、cancelled、notExecuted；模型汇总支持部分成功。接口沿用宿主管理员认证与写请求 CSRF 校验。

结果仅保留在当前插件运行内存：单条原文上限 32 MiB，总原文上限 64 MiB；容量不足清理最旧原文，保留摘要并标记 `responseEvicted`。完成任务最多 128 个、保留一小时，插件卸载后清理。大响应或原文清理不影响测试判定。正文按需读取，详情中可以继续加载下一块。

旧配置默认关闭自动禁用，不需要数据库结构迁移。多实例部署的失败计数各自独立，凭据 CAS 防止覆盖其他实例的凭据编辑，不提供跨实例统一计数。
