# Key 自动禁用与连接测试

## 自动禁用规则

在渠道「Key 管理」中配置自动禁用开关、HTTP 状态码和连续失败阈值。

| 设置 | 默认值 | 范围 |
| --- | --- | --- |
| 自动禁用 | 关闭 | 开启或关闭 |
| HTTP 状态码 | `401,403` | 400–599，支持逗号分隔的单值与区间 |
| 连续失败阈值 | 3 | 1–100 |

命中状态码后，该 Key 从同一次请求的后续选择中排除。存在其他可用 Key 和普通重试额度时，按渠道策略切换 Key；普通重试为 0 时不额外发送。认证头和 `{api_key}` 使用切换后的 Key，请求正文、会话身份和代理保持一致。

同一个客户端请求对同一个 Key 最多计一次失败，内部重试和外层再次尝试通过 Trace ID 去重。非匹配 HTTP 响应清零，网络异常、超时和取消不增减计数。判断使用原始 HTTP 状态码；状态码映射和 HTTP 200 中的业务错误不参与判断。WebSocket 握手拒绝的 HTTP 状态码参与判断。

达到阈值后，Key 被禁用并保存禁用时间、状态码、来源和累计次数。失败计数保存在运行内存，重启清空；已保存的禁用状态持续有效。多实例各自计数。

## 恢复与保存

在 Key 列表中勾选「启用」并保存，即可恢复使用。关闭自动禁用开关不会启用已禁用的 Key。

替换密钥、修改启用状态或自动禁用规则会重置相关计数。配置版本检查可防止在途请求覆盖已修改的设置。编辑冲突返回 409，需重新加载渠道再编辑。

禁用状态保存失败时，当前进程排除该 Key 并显示错误，后续请求或渠道刷新会尝试保存。保存成功前的状态以页面提示为准。

## 连接测试

「本次测试允许自动禁用 Key」独立控制测试行为，默认不勾选。勾选后使用渠道设置的状态码与阈值，与正式请求的自动禁用开关独立。

每个模型与 Key 的测试组合使用独立标识，固定测试该行 Key。命中规则时结束该行，后续组合跳过已禁用 Key。未勾选时，测试不修改失败计数或启用状态。模型发现不参与计数。

结果区分排队、运行、成功、失败、跳过、取消和未执行；模型汇总可显示部分成功。

## 结果接口

以下为插件相对路由，要求管理员会话，写请求需要 CSRF 校验。

| 接口 | 用途 |
| --- | --- |
| `POST tests/start` | 启动测试；`autoDisableKeys` 默认为 false，序列化输入上限 64 KiB |
| `GET tests/status?id=…` | 读取任务状态与进度 |
| `GET tests/results?id=…&offset=0` | 分页读取摘要，每页最多 20 条；返回 `rows`、`total`、`nextOffset`、`resultVersion` |
| `GET tests/detail?id=…&rowId=0&offset=0` | 按 UTF-8 字节位置读取响应，每次最多 64 KiB；返回 `text`、`nextOffset`、`done`、`truncated`、`evicted` |
| `POST tests/cancel` | 请求取消测试，已完成记录可继续查看 |

任务进度包含 `completed`、`total`、`runningIndex`、`resultVersion`。摘要和响应详情分别读取。

## 保存范围

结果保存在插件运行内存。单条响应原文上限 32 MiB，总原文上限 64 MiB。容量不足时清理最早保存的原文，保留摘要并标记 `responseEvicted`。

完成任务最多保留 128 个，保存一小时；插件卸载后清理。详情原文的截断或清理不改变测试判定。
