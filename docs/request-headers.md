# 请求头与会话标识

在渠道「请求头」中配置发往上游的请求头。可使用可视化或 JSON 编辑器，也可应用 Codex、Claude Code 模板后保存。

## 配置范围

| 方式 | 应用范围 |
| --- | --- |
| 所有接口共用 | 转发、模型获取和连接测试使用通用配置 |
| 按接口分别设置 | 按实际发送的 Responses、Messages 或 Chat Completions 接口选择配置 |
| 使用通用配置 | 对应接口使用通用配置；关闭后使用该接口自己的完整配置 |

模型获取使用通用请求头。连接测试使用已保存配置；从编辑表单获取候选模型时使用表单中的配置。

## 默认透传与覆盖

客户端的业务请求头默认透传，上游认证使用当前渠道 Key。本地认证头、Cookie、CSRF、Host、Content-Length、连接控制头和 WebSocket 握手头不会原样透传。

同名请求头以显式覆盖值为准。渠道的认证选择不能覆盖用户明确填写的认证头；需要跟随 Key 分配时，可在覆盖值中使用 `{api_key}`。

删除覆盖项后，该头由默认规则决定：业务头使用客户端值，认证头使用渠道认证，模板身份头按模板规则补齐。空字符串不表示删除客户端请求头。

## 占位符

| 占位符 | 含义 |
| --- | --- |
| `{api_key}` | 当前选中的渠道 Key |
| `{session_id}` | 会话标识 |
| `{thread_id}` | 线程标识 |
| `{request_id}` | 请求标识；优先使用显式配置或客户端值，缺失时为每个请求生成 |
| `{turn_id}` | 回合标识；客户端未提供时为每个请求生成 |
| `{window_id}` | Codex 窗口标识 |
| `{codex_turn_metadata}` | Codex 回合元数据 JSON |
| `{client_header:NAME}` | 指定名称的客户端业务请求头，名称不区分大小写 |

`{client_header:NAME}` 必须占据整个值。客户端未提供该头，或连接测试没有客户端请求头时，不生成这一覆盖项。经过过滤的本地认证等字段不能通过该占位符读取。

例如，以下请求头配置使用当前 Key，并在上游请求中携带客户端提供的业务标识：

```json
{
  "Authorization": "Bearer {api_key}",
  "X-Project-Id": "{client_header:X-Project-Id}"
}
```

## 模板与会话身份

Codex 和 Claude Code 模板补齐对应客户端的请求头与身份字段。Codex 模板的 `X-Client-Request-Id` 默认使用 `{request_id}`，显式配置优先。

身份来源按以下顺序选择：

1. 请求头中的显式身份覆盖。
2. 客户端请求头或消息体中提供的会话、线程及回合信息。
3. 根据对话历史匹配会话；没有唯一匹配时生成新身份。

历史匹配用于 Codex、Claude Code 模板，读取 Responses 的 `input` 或 Messages、Chat Completions 的 `messages`。插件对消息历史生成规范化摘要，后续请求携带连续历史且能唯一匹配时复用会话身份。历史缺失、冲突或缓存失效时会生成新身份；需要明确指定会话边界时，应由客户端携带会话标识。

同一次插件调用的内部重试复用完整身份。Key 切换不改变会话、线程、请求或回合标识。

身份缓存最多保存 10,000 个会话，连续 24 小时未使用后过期，按渠道、下游认证摘要和 `prompt_cache_key` 隔离。缓存只保存身份与历史摘要，不保存对话正文，重启或重载后清空。客户端提供的 `prompt_cache_key` 保持原值；它辅助隔离缓存，不能单独替代会话身份。Codex 模板在该字段缺失时使用会话标识补齐。

## 高级规则

| 配置 | 规则 |
| --- | --- |
| `headerOverride` 或接口配置中的 `headers` | 请求头名称到字符串值的映射，最多 128 项 |
| `*` | 匹配经过过滤的客户端业务请求头 |
| `re:表达式` / `regex:表达式` | 按头名匹配；表达式长度为 1–512，使用不支持回溯的正则引擎 |
| `extraParams.ReplaceHeaders` | 显式请求头覆盖；同名项以请求头编辑器中的配置为准 |
| `extraParams.PassThroughHeaders` | 最多 64 个具体头名，不接受认证头、连接头或通配符 |

通配符和正则写在 `headerOverride` 或接口 `headers` 的键中，匹配项使用客户端原值；它们的值不作为覆盖内容。`PassThroughHeaders` 不会将默认透传范围缩小为白名单。

请求头名称最长 256 个字符，覆盖值及展开后的单个值最长 8,192 个字符，不能包含控制字符。所有配置均受请求头过滤和校验规则约束。
