## 明暗适配实测

宿主的 `web/src/services/pluginAppearance.ts` 会向插件注入脚本，按 computed style 识别中性色，使用内联 `!important` 覆盖颜色。它会处理新增 DOM，切回日间恢复，保持原 sandbox 限制且不重载 iframe。

直接对 UniversalForward 使用通用适配时，禁用卡片与普通面板会被改成相同背景；插件已切换自己的黑夜配色后，浅色主按钮仍会被改为深色。该机制没有提供“插件自行配色”的退出开关。

插件在 head 中尽早安装明暗监听器，只接受父窗口发来的有效 light/dark 通知，保存真实明暗状态。2.1.2 注入监听器先于插件执行、在后续动画帧应用颜色，因此插件将 iframe 收到的消息副本中的 colorMode 投影为 light，使通用脚本保持原样式，然后由插件自己的配色入口更新 UI。父窗口持久化设置、原始消息以及请求桥不受影响。主题标识未参与插件判断，新增或删除宿主配色主题不影响明暗跟随。

这层衔接针对官方 2.1.2 原版脚本进行了真实 sandbox 浏览器测试；未来宿主若提供正式的自行配色开关，应使用该开关替换消息副本衔接。宿主若改变注入脚本，应重新运行 `tests/browser/host-appearance.cjs`，不要仅凭 Contracts 版本判断 UI 行为。

`host-appearance.cjs` 从指定官方源码读取并转译原版注入脚本，验证自动跟随、手动固定、按钮和禁用卡片配色、正文对比度、未保存表单、日志筛选、重新打开、无效来源及模式，以及 390px/320px 布局。数据和上游均为本地模拟；未安装到生产。

## 其他边界

仅启用的映射及其启用、插件平台匹配的目标参与模型隐藏。隐藏不是权限限制，原始 ID 可继续直接调用。保留插件自己的模型目录与协议配置即可。

宿主总览的持久化不改变 UniversalForward 的内存原文日志。0.3.5 新增设置文件持久化，未将原文日志写入磁盘，也未调整日志保留策略。

上游 Claude 缓存用量错误来自旧版插件过早提交简化 Usage，并非 2.1.2 自动修复；0.3.5 继续修复该问题。渠道内部重试结束后是否允许宿主继续同样由插件决策控制，宿主更新不会替代插件修复。
