# 请求 CPU 热点与 v0.3.9 验证

2026-10-29 检查 UniversalForward v0.3.8，针对「服务器 Router.Host / dotnet 进程在请求调用期间 CPU 暴涨」完成源码修复、本地复现与验证。没有取得线上 CPU trace；以下证据确认了插件内的处理热点，不代表它们占现场 CPU 的全部比例。

## 已确认的热点

1. `RequestLogCapture.CapturedStream.Observe` 在每次网络读取后将未完成 SSE 事件转为完整字符串，替换换行、从头查找边界，再复制剩余内容。长事件分成很多小块时，复制与扫描接近二次增长；一个读取块包含很多事件时，逐帧复制剩余尾串也有同样问题。日志默认开启，所以页面关闭时仍有这笔开销。
2. `ForwardStreamCollector` 在 Claude 文本、思考和签名增量到达时执行「累计字符串 + 新增量」，每次复制此前全部内容。Responses 汇总的未换行长事件也在每次读取中反复物化、扫描并复制残留。
3. `RequestLogStore.ApplyGaps` 在每个队列写操作后扫描全部丢失标记，已处理标记不清理，未插入成功的 ID 可能常驻。队列溢出后，后续写操作持续负担这些扫描和快照分配。
4. 请求准备阶段重复读取、验证渠道配置，并在模板、原生流、思考映射、系统提示词和状态剥离之间反复解析、序列化完整 JSON。长上下文及并发会放大这项线性重复成本。

未发现请求或流读取中的无界空转循环。普通重试与异常重试有次数、时限限制；快速失败与高重试配置仍会放大请求量，但默认普通重试为 0。

## 修复与日志行为

SSE 使用增量读取器，只扫描新数据，完整事件到达时解析一次；Claude 内容使用各块独立的字符串缓冲，块结束时一次写回。渠道配置按请求复用，发送规则按原顺序修改同一 JSON 对象，最终发送内容在内部重试之间复用，原始历史仍用于身份匹配。

按本次要求，实际发送正文、上游响应正文和 WebSocket 原始消息不再保留。采集端及存储端均拦截这些分段，页面查看与导出入口也过滤它们。插件收到的请求、宿主扩展参数、请求／响应头和错误信息继续保留。转发失败和模型目录失败日志保留状态、路径、类型、追踪 ID 和错误原因，不附带完整响应正文。

模型、思考参数和 Token 计数从同次解析结果提取，只在字段变化时保存快照。思考字段按事件合并；丢失标记应用后清理，流失败、取消和中断仍记录准确状态。

Token 明细为输入、输出、缓存读取、缓存写入四项。Claude 输入总量包含非缓存输入与缓存读写；OpenAI 输入已含缓存，不重复加缓存数。分片用量覆盖已出现字段，不累加重复快照，缺失字段保持已读值，显式无效值清为未知。合法 0 保留，每次上游尝试独立记录，摘要使用最后一次尝试。

## 性能复现

使用独立 .NET 10 进程对比 v0.3.8 与最终 v0.3.9 DLL。输入来自内存，每组预热一次后采样三次，输入构造和 GC 清理在计时外。记录耗时和 `GC.GetTotalAllocatedBytes`，逐次验证输出 SHA-256。日志场景经过真实 `CapturedContent.ReadAsync`、元数据结束与队列 flush，两边收到的原始请求均为空，避免保留输入影响比较。

| 场景 | v0.3.8 中位耗时 | v0.3.9 中位耗时 | v0.3.8 累计分配 | v0.3.9 累计分配 |
| --- | ---: | ---: | ---: | ---: |
| Claude 10,000 个增量，每个 100 字符 | 1,668.150 ms | 51.797 ms | 9,577.999 MiB | 28.461 MiB |
| Responses 8 MiB 单行，16 KiB 分块 | 1,548.597 ms | 16.477 ms | 8,336.161 MiB | 112.098 MiB |
| 日志 SSE 512 KiB 单行，512 B 分块 | 191.543 ms | 1.016 ms | 557.161 MiB | 8.066 MiB |

另外覆盖 Claude 2,500／5,000 个增量与 Responses 1／2／4 MiB 单行。八组输出哈希一致，最终 DLL SHA-256 为 `fbf41ebd910049c83b50b2fb13a4685036d2568d21539a73250862df02dab36d`。日志发送／响应正文保存量均为 0 B，状态、模型、思考、首字时间、Trace 和用量保持正确。

累计分配是处理期间产生的全部托管对象大小，包含后续被回收的临时对象，不等同于常驻内存。微基准耗时会受 JIT 和工作站活动影响，也不能直接换算为服务器整体 CPU 百分比。

完整原始采样、版本、DLL 和输出哈希见 [benchmark-results.json](performance/v0.3.9/benchmark-results.json)，完整表格见 [benchmark-results.md](performance/v0.3.9/benchmark-results.md)。公开的纯内存微基准源码和复运行方法见 [benchmarks/cpu](../benchmarks/cpu/README.md)。

- 827 项插件测试全部通过，含发行目录隔离加载；Release 构建将分析警告视为错误。
- 29 项真实 Router2API 2.1.2 宿主集成测试通过，使用临时存储与本地 HTTP／WebSocket 上游，覆盖重试、用量、原生流汇总、生命周期和取消。
- 日志、分页和页面导航浏览器测试通过，覆盖 Token 千分位／零／未知、旧正文分段过滤、复制导出、HTML 安全显示和移动布局。
- v0.3.9 ZIP 和内容索引校验通过，不包含宿主契约 DLL、数据库或配置文件。

发行包由 GitHub Actions 从 v0.3.9 标签构建，下载见 [GitHub Release](https://github.com/yowiv08/UniversalForward/releases/tag/v0.3.9)。线上 ZIP、内容哈希与大小以同一 Release 的 `release-index.json` 为准；上文 DLL 哈希对应本地微基准使用的二进制。发布不替换生产服务器上的插件。

日志元数据保持 1 MiB 字符解析上限；超大 JSON 或单个 SSE 事件可能无法提取模型、思考或 Token 字段。非流式可用响应契约补输入／输出，缺失缓存保持未知。原始网络响应继续完整转发。
