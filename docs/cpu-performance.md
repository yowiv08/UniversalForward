# 日志与流处理

UniversalForward 对 SSE 进行增量读取，在完整事件到达时提取模型、思考参数和用量。普通请求实时转发有效输出，非流式请求按对应协议汇总结果。

## 请求与响应

渠道设置在单次请求中复用。模板、思考映射和系统提示词作用于待发送的请求对象，内部重试使用处理后的请求体。Responses 资源状态恢复仅在匹配错误时执行。

SSE 识别 UTF-8 跨块、BOM、LF、CRLF、CR 和多行 data。协议结束事件决定完整结束状态，内容块结束或 `finish_reason` 不截断尾部用量。

输出前的缓冲和非流式响应上限为 32 MiB。流空闲超时、总时限与取消均可结束请求。

## 日志采集

请求日志采集模型、思考参数、用量、状态、耗时、请求／响应头、扩展参数和错误信息，不保存请求正文、响应正文或 WebSocket 原始消息。

元数据变化时保存对应快照。每次尝试独立记录，摘要使用最后一次尝试。连接测试通过独立的详情接口提供响应原文。

| 资源 | 限制 |
| --- | --- |
| 日志操作队列 | 默认最多 256 项 |
| 元数据解析 | 最多 1,048,576 个字符 |
| 输出前缓冲与非流式响应 | 最多 32 MiB |
| 请求日志与日志设置 | 保存在插件运行内存，重启或重载后清空 |

队列满时丢弃日志操作并标记不完整。超限事件可能缺少元数据，后续完整事件可继续解析。完整流、取消、超时和中断分别记录状态。

## 开发检查

[CPU 微基准](../benchmarks/cpu/README.md) 使用内存输入测量流汇总、日志解析和分配。其耗时与累计分配描述指定场景，不能换算为服务器整体 CPU 占用或常驻内存。

正式环境的资源消耗还取决于上下文大小、并发、模型输出、代理和重试配置。普通重试、限流重试和空回重试均受次数与时限限制。
